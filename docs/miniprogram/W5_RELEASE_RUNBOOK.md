# W5 备案、提审与发布操作手册

本手册区分“仓库已准备”和“管理员已完成”。没有平台凭证时不得勾选完成或声称已上架。

## 一、仓库发布检查

在仓库根目录依次执行：

```powershell
npm run test
npm run build
npm run build:miniprogram
npm run check:miniprogram-release
```

要求全部成功。发布检查必须显示 `ready-for-manual-gates`，真实 AppID、AppSecret、管理员
凭证和供应商密钥不得进入 Git。

## 二、公众平台前置

由管理员登录微信公众平台完成：

1. 核对中文名“我的声音相册”、英文品牌 Sound Palette、图标和简介；
2. 在实际可用类目中选择与本地声音生成抽象图片真实匹配的工具类目；
3. 完成中国大陆小程序备案并保存完成凭证；
4. 按 `PRIVACY_PLATFORM_FIELDS.md` 配置用户隐私保护指引；
5. 核对麦克风和相册用途与当前实现一致；
6. 不填写服务器域名，因为 W5 本地版不调用项目服务器。

个人主体没有真实匹配类目、备案未完成或隐私字段不一致时停止，不得上传提审版。

## 三、上传开发版本

完成 W4 最新 Android 与 iPhone 门禁后，在微信开发者工具中：

1. 导入仓库根目录并确认读取本机私有 AppID；
2. 编译并查看控制台、网络面板和包体分析；
3. 点击“上传”，版本号使用管理员确认的正式版本号；
4. 备注写明：`本地声音可视化；修复麦克风释放、临时文件清理和 1080×1440 导出`；
5. 在公众平台开发管理中确认版本号和上传时间。

Codex 不代替管理员扫码、确认上传或填写账号凭证。

## 四、体验版

1. 将刚上传的开发版本设为体验版；
2. 添加实际 Android 与 iPhone 测试人员；
3. 完整执行 `W4_QA_CHECKLIST.md`；
4. 将设备、系统、微信版本和结果写入 `DEVICE_TEST_RECORD.md`；
5. 补齐 `REVIEW_SUBMISSION.md` 中六张最新截图；
6. 任一阻塞项存在时撤销提审准备并修复，不能沿用旧二维码结果。

## 五、提交审核

1. 选择真实匹配类目；
2. 使用 `REVIEW_SUBMISSION.md` 的产品说明和功能路径；
3. 上传最新真机截图；
4. 如实说明麦克风只做本地数值分析、不识别语音、不上传声音；
5. 如实说明保存相册只在用户主动点击后触发；
6. 提交后记录审核单号、提交时间和结果。

## 六、发布与回滚

- 审核通过后仍由管理员手动点击发布；
- 发布后用 Android 与 iPhone 各做一次生产版本冒烟测试；
- 若出现持续占用麦克风、文件清理不确定、权限误导、导出失败或崩溃，立即暂停推广，
  在公众平台回退到上一稳定版本或下架问题版本；
- 发布凭证、版本号和生产冒烟结果补入 `RELEASE_EVIDENCE.md`。
